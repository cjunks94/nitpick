## (b) Findings on existing test quality

What is good, briefly: tests are table-driven where it helps, every regression test carries a comment explaining the incident that motivated it (e.g. `comment_trigger_test.go:79-93`, `httpclient_test.go:49-80`), `t.Helper` is used on every helper, all HTTP goes through `httptest`, secret fixtures are assembled at runtime to keep gitleaks at full strength, and `TestFetchFile_EscapesHostilePaths` / `TestParseFindings_CandidateSelection` / `TestIssueComment_TriggerPhrases` are exemplary behaviour tests. The problems below are about what the suite does not reach and where it relies on wall-clock time.

**B1. The 6-second server suite is one test sleeping on a production constant.**
`internal/server/coderabbit_test.go:186-215` (`TestWaitForCodeRabbit_ReturnsOnceCodeRabbitPosts`, 5.00s of the 6.04s). It sets `PollInterval: 10ms` but the comment on line 205 admits it is "clamped to the 5s floor" (`minCodeRabbitPollInterval`, `coderabbit.go:20`). Poll 1 finds nothing, the loop sleeps a real 5s, poll 2 finds the comment. Why it matters: this is the one test that proves the wait actually *returns* when CodeRabbit posts; it is also the one everybody will `-run` around. Fix: make the floor a package-level `var` overridable from tests, or give `waitForCodeRabbit` a `sleep func(time.Duration) <-chan time.Time` seam. Either brings the test to ~10ms.

**B2. No fake clock anywhere; every time-window behaviour is tested only inside the window.**
`webhook.go:378, 393, 424, 807` all call `time.Now()` directly. Consequences: `TestSpendCap` (`comment_trigger_test.go:348`) proves accumulation but not that a $0.90 entry from 61 minutes ago *drops out*; `TestIssueComment_TriggerCooldown` (`:284`) proves blocking but not that the trigger fires again after `TriggerCooldown` elapses; `shouldSkip`'s 1-hour dedup and 2-hour GC are untested entirely. A regression that made the spend window unbounded (bill capped forever after the first $5) or the cooldown permanent (maintainers locked out of `/nitpick`) would pass. Fix: add `now func() time.Time` to `Handler`, defaulted in `ensureInit`, set to a stepping fake in tests.

**B3. Real sleeps used as synchronisation.**
- `comment_trigger_test.go:465` `time.Sleep(200ms)` in `TestGoReview_BoundsConcurrency` — samples `peak` after a guess at scheduling. The assertion `got > defaultMaxConcurrentReviews` can only fail if the semaphore is removed outright; the test does not prove the 5th goroutine *blocked*, only that it had not been observed running yet. Fix: have each fn signal on a channel when it acquires; receive exactly 4, then assert a 5th receive times out on a short `select`.
- `comment_trigger_test.go:389` `time.Sleep(150ms)` in `TestDrain_WaitsForInFlightReviews` — fine as a delay, but the same test could use a `release` channel closed from the test goroutine after `Drain` is observed still blocking, removing the timing dependency.
- `coderabbit_test.go:252` `time.Sleep(100ms)` before `cancel()` — the goroutine may or may not have entered the select; the test passes either way, so it does not distinguish "honoured ctx" from "returned before ctx mattered".

**B4. Elapsed-time assertions loose enough to be near-vacuous.**
- `coderabbit_test.go:230-232`: `WaitTimeout: 50ms`, asserts `elapsed > 10s` fails. A regression that overshot the deadline by 100x would pass.
- `coderabbit_test.go:323`: `WaitTimeout: 100ms`, asserts `< 5s`.
- `coderabbit_test.go:178`: asserts `< 1s` for a no-op.
These are deliberately slack for CI jitter, which is the right instinct, but the effect is that they only catch hangs. With a fake clock (B2) they become exact.

**B5. Every comment-trigger test spawns a goroutine that nil-derefs and is silently recovered.**
`minimalHandler` (`comment_trigger_test.go:20-28`) leaves `TokenSource` nil. Every test that fires a trigger calls `goReview` → `handleCommentTriggerAsync` → `h.TokenSource.Token(...)` on a nil pointer → panic → `recoverPanic` (`webhook.go:132`, whose own comment says "Doubles as test resilience"). The tests pass, but the suite is structurally relying on a panic guard to mask the fact that nothing past line 701 of `webhook.go` is reachable from tests. That is the root cause of `handleCommentTriggerAsync` at 13% and `reviewPR` at 0% — see B9 for the missing seam.

**B6. Two tests assert less than their names claim.**
- `repo_notes_test.go:61-77` `TestFetchRepoConfig_5xxIsGraceful`: the comment (lines 64-65) says the Warn-vs-Info distinction is "asserted by the call shape rather than log capture here" — i.e. not asserted. As written it is the 404 test with a different status code. Fix: hand `fetchRepoConfig` a `slog.New(slog.NewJSONHandler(&buf, nil))` and check `"level":"WARN"` appears for 5xx and does not for 404. The log line is the documented operator signal (`webhook.go:1085-1089`).
- `comment_trigger_test.go:528-537` `TestAuthGate_OnByDefaultForStructLiteral`: checks a bool's zero value. It guards the *shape* bug CLAUDE.md describes and nothing more; the gate's *behaviour* (perm=read → no review, cooldown released) has no test. See (c).

**B7. Data races in test fakes (would fail `-race`).**
- `webhook_test.go:75-77`: `calls++` on a plain `int` inside the `httptest` handler (server goroutine), read at line 86 from the test goroutine. No happens-before edge through the socket as far as the race detector is concerned.
- `coderabbit_test.go:191-196`: `onCall` writes `f.inline` from the handler goroutine while the handler at `:38` reads it. Sequential keep-alive requests usually land on one conn goroutine, so it rarely bites, but it is unsynchronised.
Fix: `atomic.Int32` for the counter (the coderabbit fake already does this at `:23`); guard `inline` with a mutex or swap the whole slice via `atomic.Pointer`. Then get `-race` into the CI that does not exist yet.

**B8. Dead-import suppressors.**
`comment_trigger_test.go:520` `var _ atomic.Int32` (but `atomic` *is* used at `:385`), `webhook_test.go:221-222` `var _ = json.Marshal` / `var _ = base64.StdEncoding` (neither used). Delete the two unused imports and the suppressor lines; the first is redundant.

**B9. The missing seam: `ghc.NewHTTPClient(token)` hardcodes `api.github.com`.**
`webhook.go:706, 882` construct the GitHub client inside the goroutine with a fixed `BaseURL`. `Handler.TokenSource` is a concrete `*ghapp.InstallationTokenSource`, not an interface. Together these make `handleCommentTriggerAsync` and `reviewPR` unreachable from a test with a fake GitHub. Every load-bearing wiring fact in those two functions (spend-cap check before token mint, `recordSpend` on provider error, `configRef("")` skips fetch, `ignore_paths` empties → status comment, write-access gate releases cooldown) is untested for that reason alone. Fix (small): add `newGitHubClient func(token string) *ghc.HTTPClient` and `tokenSource interface{ Token(ctx, int64) (string, error) }` to `Handler`, defaulted in `ensureInit`. No production behaviour changes.

**B10. Duplication and placement.**
- `TestParseFindings` (`anthropic_test.go:14`) and `TestParseFindings_TrailingProseWithBraces` (`:100`) both carry "prose-only → 0" and "empty findings → 0" rows. Harmless, but the two tables should be merged or the second trimmed to its trailing-prose reason for being.
- `TestConfigRef_ForkReadsBaseBranch` (`comment_trigger_test.go:481`) and `TestReviewTarget_UnknownHeadOriginIsUntrusted` (`webhook_test.go:228`) overlap on the fork and same-repo rows; the latter's value is composing `HeadIsUntrusted()` with `configRef`, so keep both but drop the two duplicated rows from one.
- `TestFilterByAuthor_CaseInsensitive` (`coderabbit_test.go:288`) tests a `ghc` function from the `server` package. Move it to `ghc/httpclient_test.go`; it is why `FilterByAuthor` reads 0% per-package.
- `TestLoadCases_KeywordsParse` (`eval/runner_test.go:57`) reads the real `eval/cases/cases.jsonl`. It is a fixture lint ("every label has keywords"), not a parser test; `loadCases`'s comment-line skip, blank-line skip, malformed-line error and 1 MiB scanner buffer have no test. Keep it, but add a `t.TempDir()` table for the parser.

**B11. `t.Parallel()` is unused everywhere.** Not a defect on a 7s suite, but once B1 is fixed the server package is ~1s and the coderabbit/webhook tests are independent `httptest` servers; marking them parallel is free.

## (e) Overall assessment

The tests that exist are unusually well-motivated — nearly every one is a pinned regression with its incident written above it, and the pure-function surfaces (diff anchoring, secrets, trigger regex, findings parser, path escaping, fork trust predicate) are covered well enough that reverting any of those fixes fails the suite. The gap is structural rather than careless: `ghc.NewHTTPClient` hardcoding `api.github.com` and a concrete `TokenSource` type make `reviewPR` and `handleCommentTriggerAsync` unreachable, so the cost controls CLAUDE.md calls load-bearing are tested as isolated predicates while the wiring that makes them bite (spend-cap-before-mint, record-spend-on-error, permission-check-before-review, eval per-PR isolation, token caching) has no test at all and would not fail if quietly removed. Adding two small seams and a fake clock to `Handler` unlocks all eight tests above, drops the server suite from 6s to about 1s, and would move `server`, `eval`, and `ghapp` past the 80% bar with tests that assert behaviour rather than presence.
